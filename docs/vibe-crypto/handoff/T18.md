## Decisions and findings
- ADR is 0008 (not 0007). uv pinned to 0.11.32 in the Dockerfile.
- `gcloud run deploy --help` supports `mount-options` (GCSFuse flags, no dashes, separated by semicolons), so the volume uses `mount-options=uid=1000;gid=1000;implicit-dirs`. `printf %q` in the dry-run output escapes commas and semicolons; the printed lines are copy-paste safe in bash.
- Broker credentials: the OS keychain (`vibe-crypto connector setup`) does not exist on Cloud Run. The code confirms connector JSON files `~/.vibe-trading/<connector>.json` (read in `sdk.py` for alpaca, binance, okx and dhan, with the onboarding field names as keys) and one env variable, `FUTU_TRADE_PWD_MD5`. There are no per-broker API key env vars. Documented exactly that in `deploy/gcp/README.md`; other connectors were not checked.
- Broker table: Paper and Live columns are derived from the profile ids in `guides/portfolio-and-brokers.md` (`*-paper-trade`, `*-live-trade`, `robinhood-live-mcp`); `test_T18.py` checks all 19 rows against that matrix. Packages come from `onboarding.py` `dependency`; zerodha (`kiteconnect`), ibkr (`ib_async`) and the remote-MCP brokers (robinhood, scalable: none) come from pyproject extras and the transport logic. Market or region labels are descriptive, not generated.
- Mandate and kill switch: the repo path is the interactive `vibe-crypto` terminal chat (numbered mandate proposal, committed through `/mandate/commit`), `/halt` and `/resume`, and `vibe-crypto connector halt|resume` for remote connectors. There is no one-line CLI to create a mandate outside that flow.
- Long lines matter to `test_T01.py`: its VIBE_CRYPTO_ allow-list looks only at the first 200 characters of a line, so lines in the guide that name `VIBE_CRYPTO_WITH` keep the name early.
