Re-fetch behaviour (`uvx -v`): on every start uv asks GitHub for the commit of
HEAD (`api.github.com/.../commits/HEAD`), reads `pyproject.toml` at that commit
via raw.githubusercontent.com, and re-resolves. If the commit is unchanged, the
cached environment is reused (no reinstall); a new commit on main is picked up
on the next start with the git resolution cost. `--refresh` forces re-resolution
and re-download of metadata (about 11 s), so it is the documented update command
and the guides should say to restart the client afterwards. A client that stays
open keeps running the old server until restarted. A start therefore needs
network access to GitHub even when warm.

Probe note: fastmcp's stdio client passes only a minimal env to the child, so in
this sandbox (TLS proxy CA) the first probe failed with `UnknownIssuer`. This is
a probe/sandbox issue, not packaging; probe.py forwards `os.environ` to the child.
Real clients (Claude Code, Claude Desktop) inherit the user environment.

## Install steps for the guide

1. Install uv (macOS/Linux `curl -LsSf https://astral.sh/uv/install.sh | sh`, Windows `irm https://astral.sh/uv/install.ps1 | iex`).
2. Warm up once: `uvx --python 3.12 --with keyring --from git+https://github.com/buckleson/vibe-trading-crypto vibe-crypto-mcp --help`.
3. In Claude Code: `/plugin marketplace add buckleson/vibe-trading-crypto`, then `/plugin install vibe-crypto@vibe-crypto`.
4. Optional: `export VIBE_CRYPTO_WITH=keyring,<broker package>`; `export VIBE_CRYPTO_MCP_ENABLE_ORDERS=1` for order tools; restart.
5. Update: `/plugin marketplace update vibe-crypto` and `uvx --refresh ...`, restart.
