# T17 handoff: Claude Desktop MCPB extension, release attachment, desktop 0.4.0

## Manifest decisions
- `manifest_version` 0.3. mcpb 2.1.2 also validates 0.4 (which adds a "uv" server type), but the "uv" type
  bundles a pyproject and is not what we want, and 0.3 is accepted by more Claude Desktop versions. Kept 0.3.
- `server.type` "binary" with `entry_point` "uvx" and `mcp_config.command` "uvx". Validate and pack both accept it
  (entry_point is not required to exist in the bundle). Nothing is bundled but manifest.json, icon.png, README.md
  (`.mcpbignore` excludes the rest). The system uvx from PATH is launched.
- Source: GitHub archive zip of `main` (no git needed). Works, see below.
- user_config: `extra_packages` (default `keyring`), `enable_order_tools` (default false, mapped to
  `VIBE_CRYPTO_MCP_ENABLE_ORDERS`).
- icon.png is a 512x512 resize of assets/icon.png (was 1024x1024).

## Zip vs git
`uvx --python 3.12 --with keyring --from <main.zip> vibe-crypto-mcp --help`: exit 0, cold 15 s (proxy-cached wheels;
a real first run on a clean machine will be slower). Warm start of the full MCP handshake: about 4.5 s.
Note: this tested the pushed `main`, which does not yet contain this session's uncommitted changes.

## Validation
- `mcpb validate manifest.json`: passes (icon check passes).
- `mcpb pack extensions/claude-desktop <scratch>.mcpb`: 3 files only (manifest.json, icon.png, README.md), ~22 kB.
  `mcpb info` works (unsigned warning only).
- Launch simulation (venv python -I, fastmcp StdioTransport, manifest command with defaults, full parent env so the
  proxy variables reach uv): listed 87 tools, twice.
