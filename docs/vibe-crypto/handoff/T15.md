# T15 handoff: remote MCP token auth and opt-in order tools

## Summary
http and sse transports now support a shared token (ADR 0008). A non-loopback bind without a token refuses to start (exit 2). Order tools are opt-in via flag or process env only.

## Flags, env, URLs
- `--token` / env `VIBE_CRYPTO_MCP_TOKEN`: 16-256 chars of `A-Za-z0-9_-`. Generate: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
- `--allowed-hosts a,b` overrides env `VIBE_TRADING_MCP_ALLOWED_HOSTS`. With a token and no list the host guard allows `*`; without a token the loopback default applies.
- `--enable-order-tools` / process env `VIBE_CRYPTO_MCP_ENABLE_ORDERS=1` (`.env` is never read for it). Registers `trading_place_order`, `trading_cancel_order` (destructiveHint true, readOnlyHint false). Default tool list unchanged (87).
- Client auth: `Authorization: Bearer <token>` or URL prefix: `https://<host>/<token>/mcp` (http), `https://<host>/<token>/sse` (sse). Else 401 with `WWW-Authenticate: Bearer realm="vibe-crypto"`; `/.well-known/*` gives 404.
- Refusal text: "Refusing to listen on <host> without a token: ... See guides/share-with-friends.md."
- Token given: uvicorn `access_log=False`. No token: startup warning. Chat panel config pins `VIBE_CRYPTO_MCP_ENABLE_ORDERS=0`.
- Path-prefix works via ASGI `root_path` (path unchanged); verified end to end for `/<token>/mcp` and `/<token>/sse` with real fastmcp clients.
