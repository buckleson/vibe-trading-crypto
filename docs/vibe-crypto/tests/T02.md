# T02 tests: remove app authentication, keep local request guards

The tests run offline and give the same result every time. They use FastAPI's in-process TestClient, bare ASGI request scopes, a mocked `fetch` and `EventSource`, and an intercepted `child_process.spawn`. They contact no exchange, Anthropic API or real backend. No implementation code was changed.

```
cd /home/user/vibe-trading-crypto && python -m pytest agent/tests/vibe_crypto/test_T02.py -q

cd /home/user/vibe-trading-crypto/desktop/electron && npm run build && node scripts/test-T02.mjs
```

### 1b. `_require_local_request` (unit, bare ASGI scope)
- Loopback peers return the loopback Principal (`LOOPBACK_TRUST`). Tested peers: `127.0.0.1`, `127.8.9.10`, `::1`, `localhost`, `testclient`.
- Non-local peers get 403 with "Vibe Crypto only accepts requests from this computer". Tested peers:
  - `203.0.113.7`, `10.0.0.5`, `192.168.1.20`
  - `172.17.0.1` while Docker trust is off
  - `0.0.0.0`, `2001:db8::1`
  - a non-IP string, an empty host, and no client at all
- Safe methods skip the Origin check, even with an evil Origin and `Sec-Fetch-Site: cross-site`. Tested: `GET`, `HEAD`, `OPTIONS`, and lower-case `get` and `head`.
- Unsafe methods with a foreign Origin get 403 "Cross-site request denied".
  - Methods: `POST`, `PUT`, `PATCH`, `DELETE`, plus mixed case.
  - Origins:
    - `https://evil.example`
    - `localhost.evil.example`
    - `127.0.0.1.evil.example`
    - `null`
    - `file://`
    - `chrome-extension://`
    - a LAN IP
- `Sec-Fetch-Site: Cross-Site` rejects writes even when there is no Origin.
- Local writes pass with:
  - no Origin
  - a loopback Origin on 127.0.0.1, localhost, `[::1]` or `127.0.0.2`
  - a same-site Origin
  - `Sec-Fetch-Site` set to `same-origin`, `same-site` or `none`
- An Origin that matches a custom request Host passes. The same host on another port is rejected.
- Ordering: the cross-site check runs before the peer check. A remote write without an Origin gets the local detail.
- Credentials never admit a remote peer. Tested: Bearer, empty Bearer, Basic and `X-API-Key`, each with `API_AUTH_KEY` and `VIBE_TRADING_API_KEY` set.
- Bad or garbage Authorization headers never reject a local peer.
- Docker gateway: `172.17.0.1` is local only when `VIBE_TRADING_TRUST_DOCKER_LOOPBACK=1` and it is the default gateway. A different 172.x address is still rejected.

### 1c. Public dependencies
- Each of `require_auth`, `require_event_stream_auth`, `require_local_or_auth` and `require_settings_write_auth`:
  - is a coroutine whose only parameter is `request`, with no default
  - has a docstring that says "Local request guard" and "ADR 0002"
  - is the same object that `api_server` exports
- `require_auth` returns the loopback Principal. The other three return None.
- All four reject remote peers (403, local detail) and cross-site writes (cross-site detail).
- `_require_shutdown_authorization` takes `request` as a keyword-only argument and enforces the same two rejections.

### End to end through the app (TestClient)
- Routes covered, one per guard flavour:

  | Guard | Route |
  | --- | --- |
  | `require_auth` | `GET /skills` |
  | `require_local_or_auth` | `GET /settings/data-sources` |
  | `require_settings_write_auth` | `POST /api/paper-accounts` |
  | `require_event_stream_auth` | `GET /alpha/bench/{id}/stream` |
  | `require_event_stream_auth` | `GET /sessions/{id}/events` |

  - A local client with no headers never gets 401 or 403.
  - Remote IPv4 and IPv6 clients get 403 with the exact detail.
  - Remote clients that send a Bearer header plus `?api_key=` and `?ticket=` still get 403.
- No `WWW-Authenticate` header is sent.
- Cross-site POST, PUT, PATCH and DELETE are rejected with 403, or 405 where the method does not exist. A cross-site GET is allowed.
- DNS rebinding:
  - Rejected with 403 "Untrusted local API host": `evil.example`, `evil.example` with a port, `attacker.localhost.evil`, a LAN IP and `localhost.evil.example`.
  - Accepted: `localhost`, `localhost:8899`, `127.0.0.1:5173`, `[::1]:8899`, `LOCALHOST.` and `testserver`.
  - `API_ALLOWED_HOSTS` extends the allow-list.
- `API_AUTH_KEY` and `VIBE_TRADING_API_KEY` have no effect for any value: `anything`, empty, or `Bearer x`.
- Security headers (CSP, nosniff, `X-Frame-Options: DENY`) are present on 200, 403 and 404 responses, for local and remote clients, and on rebinding rejections.
- `/docs`, `/redoc` and `/openapi.json` return 200 for local clients and 403 for remote ones.
- The shutdown route rejects remote and cross-site requests. `os.kill` and `os._exit` are mocked.
- Access-log redaction of `api_key=` and `ticket=` is kept, and other params are untouched.

## Frontend: `frontend/src/__tests__/vibe-crypto/T02.auth-removal.test.tsx`

### apiAuth removal
- `lib/apiAuth.ts` and its test are deleted, and importing the module fails.
- No production source references `apiAuth`, `sse-ticket`, `withAuthTicket`, `get/setApiAuthKey`, `vibe_trading_api_auth_key` or `authHeaders`. Locales and the T01/T02 tests are excluded.
- No production source builds a Bearer or `Authorization` header.

### api.ts request helper
A stale `vibe_trading_api_auth_key` is placed in localStorage and sessionStorage for these tests.
- GET sends only `content-type`.
- POST keeps the method and body, with no Authorization.
- Caller headers are merged and no auth is added, whether passed as an object, a `Headers` instance or tuples.
- The pre-T02 Content-Type merge is unchanged. The default `Content-Type` and the caller's lower-cased key are both kept, which is the existing behaviour and is documented here, not changed.
- A caller-supplied Authorization is passed through: the helper does not mint one.
- The legacy key is never read from storage.
- An empty body resolves to `{}`.
- `uploadFile` sends FormData with no headers.
- `downloadGeneratedReport` sends no headers and URL-encodes the report id.
- 401 and 403 still map to auth-required errors. 404, a plain Error and null do not.
- No `/auth` URL is ever fetched.

### SSE URL helpers
- `swarmSseUrl`, `alphaBenchStreamUrl` and `alphaCompareStreamUrl` return plain strings synchronously. They have no `ticket`, `api_key` or `token` param and make no fetch.
- Special characters are encoded. An empty id is accepted.

### useSSE
- The exact URL opens synchronously, with no init option and no fetch. An existing query string is untouched.
- Reconnect timing and URLs:
  - Each reconnect uses the same URL with no ticket.
  - The first reconnect waits exactly 100 ms (nothing opens at 99 ms) and the second waits 200 ms.
  - Backoff is capped at `maxRetryMs`.
- Resume appends only `Last-Event-ID`.
- `disconnect` stops retries.
- The source has no ticket or key plumbing and calls `new EventSource(url)`.

### Settings page
This block renders with a mocked API.
- There is no "Local API access", "Server API key" or "Stored only in this browser" text and no matching labelled field.
- The legacy storage key is never written.
- The source has no `localApiKey`, `setLocalApiKeyState`, `setApiAuthKey`, `getApiAuthKey` or `localApiAccess`/`serverApiKey`/`localApiKeySaved`. It still has provider key fields.

### Vite proxy
- `PROXY_PATHS` parses and still covers `/api`, `/sessions`, `/settings/llm`, `/live` and `/upload`.
- There is no `/auth` entry or regex anywhere in the config.
- There are no duplicate entries.

## Desktop: `desktop/electron/scripts/test-T02.mjs`

- `main.ts mints and injects no key`: `src/main.ts` and `dist/main.js` have no `apiAuthKey`, `API_AUTH_KEY`, `onBeforeSendHeaders`, Authorization, Bearer or `randomBytes`.
- `main.ts still hardens the renderer session`: the permission handler denies, with `contextIsolation`, no `nodeIntegration` and the sandbox on. `BackendManager` receives no key.
- `backend-manager option type has no apiAuthKey`: the only `API_AUTH_KEY` line is `delete childEnvironment.API_AUTH_KEY;`.
- `child env drops API_AUTH_KEY: ...`: runs `BackendManager.start()` from `dist` with `spawn` intercepted, in 5 scenarios:
  - no key anywhere
  - an inherited key
  - an inherited empty key
  - a key in the credential store
  - both inherited and stored

  In each scenario:
  - The child environment has no `API_AUTH_KEY` and no leaked value.
  - Provider and broker credentials (`OPENAI_API_KEY`, `BINANCE_API_KEY`) and `VIBE_TRADING_DESKTOP_SECURE_CREDENTIALS=1` are kept.
  - The backend arguments include `serve --host 127.0.0.1`.
- `scripts no longer pass or assert a key`: the smoke, update-safety and backend-resolution scripts contain no key, Authorization or Bearer.
- `THREAT_MODEL describes the local guard, not a per-launch key`: the file mentions ADR 0002, "no login or API key", loopback, Host and cross-site. It does not mention a per-launch key, Authorization header injection or `onBeforeSendHeaders`.
