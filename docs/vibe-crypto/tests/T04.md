# T04 tests: paper runs backend

File: `agent/tests/vibe_crypto/test_T04.py` (241 cases with parametrisation). Offline and deterministic: the backtest engine is a fake callable that writes synthetic artifacts, the clock is injected, and no exchange or Anthropic API is called. Implementation code was not modified.

Result at time of writing: 241 passed in about 5 s on its own, and 285 passed with the T04 developer tests and existing path and account tests.

## Test cases

### Constants and exports
- `test_constants_match_spec`: `WARMUP_DAYS` and `INTERVAL_MINUTES` exactly as in the spec.
- `test_package_exports`: the package re-exports `PaperRuns` and `PaperRunNotFound`, `PaperRunNotFound` is a subclass of `KeyError`, and `_run_backtest` exists.

### forward_start
- `test_forward_start_table`: 21 rows. Covers 1D, 1W and 1M (next UTC date, including exact midnight, year rollover and leap day). Covers 4H (mid-bar, exact boundary moves to the next boundary, midnight boundary, day rollover). Covers 1H (year rollover, 1 microsecond past a boundary). Covers 30m, 15m (exact boundary, just before a boundary), 5m (day rollover) and 1m (with and without seconds).
- `test_forward_start_converts_other_timezones_to_utc`: +05:00 and -08:00 inputs are normalised to UTC, including an exact boundary.
- `test_forward_start_naive_is_treated_as_utc`.
- `test_forward_start_intraday_invariants`: 6 intervals x 8 times of day. Checks the format, that the result is after the start by at most one interval, and that it is aligned to the interval since midnight UTC.
- `test_forward_start_daily_format`: 1D, 1W and 1M return `YYYY-MM-DD`.

### create
- Shape and defaults: the exact key set, a 12-hex id, `status` active, `state` waiting, the null fields, UTC `started_at`, the 4H `evaluation_start`, a 180-day warm-up, and no backtest call.
- Persistence: `paper_run.json` equals the returned document, `source_config.json` equals the source config, only `*.py` files are copied, no `config.json` before refresh, and no leftover `*.tmp` files.
- The run lives under `root` and never under `runs_dir`.
- The label, `initial_cash` and `warmup_days` overrides are applied.
- Default label: first 3 codes, trimmed to 80 characters (default and explicit).
- Missing `source`, `interval` and `initial_cash` fall back to `auto`, `1D` and 100000.
- Every valid interval gives the matching `evaluation_start` and `warmup_start`.
- Ids are unique over 20 creates. A 200-character `run_id` is accepted. A non-UTC clock is stored as UTC.
- Invalid inputs (ValueError, and nothing written):
  - bad `run_id`: empty, `.`, `..`, path traversal, slashes, spaces, more than 200 characters, a trailing newline, non-ASCII, None, an int
  - a missing run, a missing `signal_engine.py`, or a `config.json` that is not valid JSON
  - bad `codes`: missing, empty, a string, ints, or containing None
  - a bad interval: `2H`, `1d`, `1h`, empty, `daily`, `4h`
  - bad cash: 0, a negative value, NaN, plus or minus infinity, or a string, as an argument or from the config (a valid explicit override wins over a bad config value)
  - `warmup_days` of 0 or less than 0

### get / list / detail
- Malformed ids (uppercase, wrong length, traversal, non-hex, None, an int) raise `PaperRunNotFound` from get, detail, refresh, stop and delete.
- A well-formed unknown id gives NotFound everywhere, and no backtest is called.
- A corrupt `paper_run.json` gives NotFound, and `list` skips it.
- `list` is empty when the root is missing. It is ordered newest first and ignores foreign directories, directories without a document, and stray files.
- `detail` without artifacts returns empty lists.
- `detail` with artifacts: the equity rows, the trades newest first with exact field values, NaN mapped to None, no positions when flat, and strict JSON (`allow_nan=False`).
- Positions come from the last row only. Short (negative) weights are kept and `1e-12` is filtered out.
- NaN equity and drawdown become None, and the summary drawdown ignores NaN.
- Garbage artifacts (an empty or binary CSV, or a header-only CSV) do not raise.
- `detail` and `get` never call the backtest.

### refresh: config
- The config written equals the config the engine sees. `start_date` is the warm-up start, `end_date` is today's UTC date, and `evaluation_start_date` and `initial_cash` are set. `warmup_bars` and `frozen_data_manifest` are removed, other keys are kept, and the source run's config is untouched.
- An overridden cash value is used, and `end_date` moves with the clock while the evaluation and warm-up starts stay fixed.
- `end_date` uses the UTC date for a non-UTC clock.
- A source that has both `warmup_bars` and `evaluation_start_date` produces a config with only the paper `evaluation_start_date`.
- Stale artifacts are deleted before the engine runs.
- `last_refreshed_at` is set and persisted.

### refresh: summary and states
- Summary math: equity, pnl, total return, max drawdown of 0 or less, sharpe, trade count, bars and `as_of`. A loss case with overridden cash is also checked.
- Sharpe column variants: `Sharpe Ratio`, `sharpe_ratio`, none, and NaN.
- With no `metrics.csv` and no `trades.csv`: sharpe is None and the trade count is 0. An ok envelope with no `equity.csv` gives a None summary.
- Waiting: each of the 4 markers, a marker in `stderr`, and a marker in a nested field. Waiting after ok clears the summary. An exception carrying a marker also gives waiting.
- Error: messages are truncated to 500 characters. The error falls back to `stderr` and then to the envelope text. Malformed envelopes (non-JSON, a list, null, or no status) and a None return give error. Exceptions are caught (`RuntimeError: boom`). Recovering from error clears `last_error`.
- The `_run_backtest` patch point is looked up at call time (patched after construction), and the real `_run_backtest` delegates to `src.tools.backtest_tool.run_backtest`.

### stop / delete / concurrency
- `stop` sets `stopped_at`. A second stop keeps the first timestamp. A refresh after stop uses the stop date as `end_date` and stays stopped.
- `stop` does not call the backtest, and it keeps the last results.
- `delete` removes only that paper directory (the source run and other paper runs remain). A second delete gives NotFound.
- 4 threads refreshing the same id, through separate `PaperRuns` instances, never overlap (`max_active == 1`).

### Paths
- `PaperRuns()` defaults follow `VIBE_TRADING_HOME`, and paper runs are not under `get_runs_dir()`.
- `_default_run_roots()` includes `<runtime_root>/paper-runs`. `safe_run_dir` accepts a paper directory and rejects other directories.
- The directory the service passes to the backtest passes `safe_run_dir`.

### REST routes (TestClient on `api_server.app`, `_run_backtest` monkeypatched)
- Exactly 6 `/api/paper-runs*` routes with the right methods, and the paper accounts routes still exist. The handlers are sync. `api_server.py` has no paper-runs code.
- The full lifecycle: list, create, get (no recompute), refresh, stop twice, delete, then 404.
- The list is ordered newest first.
- 404 with `Paper run not found` for 5 ids x 4 endpoints, with no backtest call.
- 422 from the schema: a missing or empty `run_id` or one of 201 characters, a label of 81 characters, cash of 0, negative, inf, NaN or a string, `warmup_days` of 0, 5001 or 1.5, an extra field, or a non-string `run_id`. No paper directory is created.
- 422 from the service, with its message: a missing run, a missing `signal_engine`, traversal, `..`.
- Boundaries are accepted: an 80-character label, cash of 0.01, `warmup_days` of 5000 and of 1, and explicit nulls.
- A missing or invalid JSON body gives 422.
- Refresh through the API reports the waiting and error states.
- Loopback client (127.0.0.1) POST, refresh, stop and delete work with no Origin header and with a localhost Origin.
- Responses are strict JSON (no NaN or infinity).
