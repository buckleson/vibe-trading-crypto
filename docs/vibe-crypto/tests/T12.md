# T12 tests: read-only wallet connect

All tests are vitest under `frontend/`, offline and deterministic. The wallet is a fake
EIP-1193 object on `window.ethereum` (request / on / removeListener). `sonner` is mocked,
`navigator.clipboard.writeText` is a stub, and global `fetch` is stubbed to prove no backend calls.
The real i18n setup is used, so strings come from the `defaultValue`s (and must keep matching
once T13 adds `wallet.*` English keys).

## Commands

```
cd /home/user/vibe-trading-crypto/frontend
npx vitest run src/__tests__/vibe-crypto/T12.walletLib.test.ts src/__tests__/vibe-crypto/T12.walletButton.test.tsx
npx tsc -b
```

## `frontend/src/__tests__/vibe-crypto/T12.walletLib.test.ts` (59 cases)

formatUnits
- 0 -> `0`; 1 wei -> `0` (truncated); 0.0001 ETH -> `0.0001`; 0.00009999 ETH -> `0` (rounds down)
- 1, 1.5, 2.00001 -> `2` (no trailing dot/zeros), 1.9999, 1.999999999999999999 -> `1.9999` (never rounds up)
- thousands separators: 999, `1,000`, `1,234,567.8912`, `1,000,000,000`
- exact precision far above Number.MAX_SAFE_INTEGER (27-digit integer part)
- trailing zero trimming (`1.1`, `1.01`)
- custom decimals 6 (USDC), decimals 0, maxFraction 0 / 2 / 8, defaults equal (18, 4)
- negative values get a leading minus; 10^40 never yields `e`, NaN or Infinity

shortAddress
- `0x1234…5678` with U+2026, length 11, no em dash, no `...`, checksum casing kept

CHAIN_INFO / chainLabel
- exact table of the 8 specified chains; known lookups (Polygon POL, Avalanche AVAX)
- fallback `Chain N` / ETH for 1337, 31337, 0, 999999

getProvider
- null with no injected wallet; returns `window.ethereum` when present

Request wrappers
- connectWallet -> `eth_requestAccounts` (single call); getAccounts -> `eth_accounts` and may return []
- getChainId parses 0x1, 0xa, 0x38, 0x89, 0x2105, 0xa4b1, 0xA4B1, 0xa86a, 0xaa36a7
- getBalanceWei sends `[address, "latest"]`, returns an exact bigint (1.5 ETH), 0x0 -> 0n, 2^256-1
- provider errors propagate unchanged

isUserRejection
- true for `{code:4001}` and Error with code 4001; false for `"4001"` code, 4100, -32002, -32603,
  plain Error, `{}`, null, undefined, string, number

## `frontend/src/__tests__/vibe-crypto/T12.walletButton.test.tsx` (48 cases)

Disconnected
- Connect wallet button with icon, `aria-haspopup="dialog"`, `aria-expanded="false"`, no dialog
- no provider calls on mount when the flag is unset or `'0'`

No provider popover
- browser: title, install text, `Get MetaMask` link (href, `_blank`, `noopener noreferrer`), no Copy link
- desktop (`vibeDesktop.isDesktop`): text with interpolated `window.location.origin`, no raw `{{url}}`,
  no MetaMask link, Copy link writes the origin and toasts success
- `isDesktop: false` uses the browser variant
- button toggles popover closed, aria-expanded tracks state
- focus moves into the dialog; Escape closes; inside mousedown keeps it open; outside mousedown closes
- other keys (Enter, Tab) do not close
- clipboard failure shows an error toast, no success toast

Connect flow
- flag becomes `'1'`; button shows success dot (8px), mono 13px short address, chain name `hidden md:inline`
- popover: full address, Ethereum badge, `1.5 ETH` with tabular-nums, read-only and forget notes, w-72 bg-popover
- eth_getBalance sent for the connected address at `latest`
- BNB Smart Chain shows `1.5 BNB`; unknown 0x539 shows `Chain 1337` and ETH; zero balance shows `0 ETH`
- 4001 rejection toasts `Wallet connection was declined`, flag not set, no dialog
- other error toasts its message (not the declined text); non-Error rejection is stringified
- empty account list from eth_requestAccounts stays disconnected
- provider present never opens the no-wallet popover

Connected popover actions
- Copy address writes the full address and toasts `Address copied`
- Refresh re-reads balance (2 ETH), exactly one extra eth_getBalance, no second eth_requestAccounts
- failed refresh shows an inline `role=alert`, wallet stays connected
- Forget wallet: flag `'0'`, popover closed, back to Connect wallet, zero provider calls (no revoke)
- after Forget a remount makes no provider calls
- connected popover closes on Escape and resets aria-expanded

Provider events
- accountsChanged([]) and accountsChanged() disconnect and set flag `'0'`
- accountsChanged([other]) switches the short address and fetches the new account's balance
- accountsChanged while never connected does not connect
- chainChanged updates badge to Polygon and balance to `1.5 POL`
- chainChanged while disconnected makes no requests
- exactly one listener per event; both removed on unmount
- provider without on/removeListener still connects and unmounts cleanly

Auto-restore
- flag `'1'` restores via eth_accounts, fetches balance, never calls eth_requestAccounts
- flag `'1'` but eth_accounts returns []: flag reset to `'0'`, only eth_accounts was called
- flag `'1'` with no provider: nothing happens, click shows no-wallet popover
- eth_accounts rejection during restore is swallowed (no toast)
- localStorage throwing on get/set still allows connecting

Read-only guarantees
- full session (connect, refresh, chain switch, account switch, forget) only uses the four read methods; fetch never called
- rendered copy has no em dash
- the four wallet source files contain no signing/transaction/chain-switch/revoke methods, no fetch/axios/api client,
  no em dash, and no direct `localStorage.` (must use safeGet/safeSet)
- package.json has no wallet SDKs (ethers, viem, wagmi, web3, MetaMask SDK, rainbowkit, walletconnect)
- `window.ethereum` is declared in lib/wallet.ts, not desktop.d.ts
- TopBar still renders `<WalletButton />`
