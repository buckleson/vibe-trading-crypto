# T16 tests: uvx install from GitHub and Claude Code plugin marketplace

File: `agent/tests/vibe_crypto/test_T16.py`. The developer's six tests are unchanged; the only edit to them is that the em dash literal is now written as `"\u2014"`. The test engineer appended 29 test functions after them. The file has 35 test functions and 55 cases after parametrisation. Implementation files were not modified.

The default run is offline. It uses the local `claude` CLI if one is found: on `PATH`, or else `/opt/node22/bin/claude`. It does not log in, and the plugin is installed into a temp HOME. Four tests reach GitHub and PyPI through uvx. They are skipped unless you set `VIBE_CRYPTO_NETWORK_TESTS=1`, and they are also marked `integration`.

## Run

```
cd /home/user/vibe-trading-crypto && . .venv/bin/activate
python -m pytest -q agent/tests/vibe_crypto/test_T16.py
python -m pytest -q -rs agent/tests/vibe_crypto/test_T16.py agent/tests/vibe_crypto/test_T01.py agent/tests/vibe_crypto/test_T14.py
VIBE_CRYPTO_NETWORK_TESTS=1 python -m pytest -q agent/tests/vibe_crypto/test_T16.py -k uvx
/opt/node22/bin/claude plugin validate /home/user/vibe-trading-crypto
/opt/node22/bin/claude plugin validate /home/user/vibe-trading-crypto/plugins/vibe-crypto
ruff check agent/tests/vibe_crypto/test_T16.py
```

## Coverage

### Manifests and layout
- Plugin names in the marketplace are unique and in kebab-case, and the owner is set.
- `source` is relative (`./`), contains no `..`, and resolves to `plugins/vibe-crypto` inside the repo.
  - `claude plugin validate` does not check that `source` exists (verified with a marketplace pointing at `./nope`, which passes), so this test is the only guard.
- These versions are all semver and equal:
  - marketplace metadata
  - the marketplace plugin entry
  - plugin.json
  - `desktop/electron/package.json` (0.4.0)
- plugin.json and the marketplace entry have the same description, the MIT license (and `LICENSE` exists), and GitHub URLs.
- The plugin directory holds exactly the expected 8 files, so stray files such as hooks, `__pycache__` or secrets fail the test.
- `git check-ignore` confirms that no plugin or marketplace file is gitignored. An ignored file would never reach friends.

### `.mcp.json`
- The args list equals the canonical one exactly.
- There is no `env` block, so `VIBE_CRYPTO_MCP_ENABLE_ORDERS` and the token are never baked in.
- There is no `--refresh` (it would slow every start).
- The git source is not pinned to a ref.
- `${VIBE_CRYPTO_WITH:-keyring}` expansion was simulated with shell semantics for four cases:
  - unset
  - empty
  - `keyring,alpaca-py`
  - three packages

  With the variable unset or empty, the joined command equals the canonical stdio command exactly. That Claude Code really expands the variable was verified by T16 dev in a real install (see handoff/T16.md). It is not unit-testable here without a model session.

### Commands and skill
- Frontmatter is parsed with `yaml.safe_load`. The tests reject a BOM or CRLF line endings, and require a non-trivial `description`, no `allowed-tools` and no `model`.
  - connect-broker and paper-run must have `argument-hint` and `$ARGUMENTS`.
- The skill `name` is `safe-trading`. Its description names the order tools, `paper_run_`, connecting a broker and live.
- The skill body must contain every rule from the spec. The tests check 21 phrases, including all eight order fields, the explicit yes in the current message, no loop/batch/retry, mandate, kill switch, no workaround, secrets, the opt-in flag and not financial advice.
- Secrets:
  - connect-broker has the exact `connector setup <profile-id> --connection-id <short-id>` template, the hidden prompt, the keychain and `VIBE_CRYPTO_WITH=keyring,<dependency>`.
  - In every plugin file, any line that combines paste, enter, send or provide with key, secret, password or TOTP must be negated.
- portfolio, status and paper-run never instruct calling an order tool. portfolio does not name an order tool at all, and paper-run says "no real orders" and defaults to 10000.
- status names `VIBE_CRYPTO_MCP_ENABLE_ORDERS=1`, the `uvx --refresh` update and a restart.
- The plugin README must contain:
  - the install commands
  - both uv installers
  - the exact canonical warm-up command
  - the 185 packages note
  - the env vars
  - the update steps
  - all four slash commands
  - the guide link
- Relative links in the README stay inside the repo and must exist. The only exception is the T18 guide, which skips the test while it is missing.

### Cross-checks against the real code (in-process, offline)
- Every backticked tool name in the plugin markdown exists in the FastMCP server, or is one of the two opt-in order tools.
- The default tool count equals the "87 tools" claim in plugin.json, and the order tools are absent by default.
- Tool parameters used by the commands exist:
  - `trading_check.connection_id`
  - `trading_select_connection.connection`
  - `paper_run_start.run_id` and `initial_cash`
- The connector count is at least the "19 broker connectors" claim. Every onboarding `dependency` is a bare PEP 508 name, so `--with keyring,<dep>` is well-formed.
- The CLI parser accepts `connector setup <real profile id> --connection-id my-conn`, and rejects the command without a profile.
- pyproject:
  - the entry points resolve to callables
  - `requires-python` allows 3.12
  - `mcp_server` is in py-modules
  - every file under `agent/src/skills` (at least 89 SKILL.md files) is covered by the `package-data` globs, which guards the "89 skills" result after a uvx install

### claude CLI
- `validate` exits 0 for the repo root and for the plugin, prints "Validation passed" and shows no error marker.
- Negative controls show that `validate` is not a no-op on this layout. It fails on a copy of the plugin with broken plugin.json, and on a copy of the marketplace with a duplicate plugin name.
- An isolated install with a temp HOME and `CLAUDE*` env vars stripped:
  - marketplace add, install and list succeed, and the list shows version 0.4.0
  - installing an unknown plugin fails

### Network (opt-in)
- `uvx --help` runs for three forms: the exact one-liner from the brief, the canonical `--with keyring` form, and `vibe-crypto connector setup --help` through the same `--from`.
- A stdio probe from a temp cwd, with HOME and VIBE_TRADING_HOME pointing at temp dirs, lists exactly 87 tools, `paper_run_list` returns status ok, and there are at least 89 skills.
  - The probe forwards `os.environ` because fastmcp's client strips the environment otherwise (TLS proxy CA, see handoff/T16.md).
