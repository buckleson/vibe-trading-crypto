# T18 tests: share guide, ChatGPT self-hosting (tunnel, Cloud Run), README and handoff

All checks are offline and deterministic. No real `gcloud` command runs. The deploy and teardown scripts run either with `--dry-run`, or in "mocked real mode": without `--dry-run`, against a fake `gcloud` that is first on PATH. Each test checks this before it runs. The fake records every call and its stdin, snapshots the `--source` directory, and returns fixed values (project number, service URL, existing token). The fake can also exit 1 on a chosen subcommand. The two server tests start the real `vibe-crypto-mcp` console script on a free local port.

## Commands

```

cd /home/user/vibe-trading-crypto && bash tools/ci_grep_gates.sh
cd /home/user/vibe-trading-crypto && /opt/node22/bin/claude plugin validate . && /opt/node22/bin/claude plugin validate plugins/vibe-crypto
```

The two shellcheck tests in test_T18.py skip when `shellcheck` is not on PATH. To run them, link the shellcheck-py binary into a directory and put that directory first on PATH. Do not prepend the uv archive `bin` itself, because it also holds a `python` without pytest.

## Observations (not failures)

- teardown.sh deletes the Cloud Run service before it asks to confirm `--delete-data`. A refused confirmation therefore still removes the service, while data and secret are kept. The script says "Nothing else was deleted", which is accurate.
- Dry-run output is `printf %q` quoted, so the volume options appear as `name=data\,type=...\;gid=1000...`. They are valid bash and round-trip exactly, as tested.
