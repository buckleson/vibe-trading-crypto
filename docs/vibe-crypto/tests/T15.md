## Coverage

### Token validation
- Boundaries: 16 and 256 characters are accepted. Surrounding whitespace is stripped.
- Rejected values:
  - 15 or 257 characters
  - whitespace only
  - dots, `+` or `=`
  - non-ASCII characters
  - a NUL byte
- The error message names `VIBE_CRYPTO_MCP_TOKEN` and `token_urlsafe`, and never echoes the rejected value.

### Loopback detection
- Treated as loopback:
  - `127.255.255.254`
  - padded `127.0.0.1`
  - `Localhost`
  - the long-form `::1`
- Not treated as loopback:
  - an empty string
  - `[::]`
  - `10.0.0.1`
  - `localhost.example.com`
  - `127.0.0.1.nip.io`
  - `::ffff:8.8.8.8`
  - garbage strings

### `_network_security_settings`
- **Refusal:** a non-loopback bind without a token is refused even when an allowed-hosts list is given. The message contains:
  - the host
  - `VIBE_CRYPTO_MCP_TOKEN`
  - `--token`
  - `guides/share-with-friends.md`
- **Blank token:** treated as no token.
- **Invalid token:** rejected even on loopback.
- **Wildcard host:** a token with a blank host list yields `["*"]`.
- **Explicit host list:** an explicit list replaces both the wildcard and the loopback default.

### Middleware stack
- With no token, the stack is the host guard then the origin guard, with no token guard (`None` and `""` both count as no token).
- With a token, there are three middlewares and the token guard is last.

### `_TokenGuardMiddleware`

**Accepted**
- With the path form, the path stays unchanged and `root_path` becomes `/<token>`. This was checked for `/mcp` and `/messages/`.
- `/.well-known/*` with a valid Bearer header passes through.
- `lifespan` and unknown scope types pass through.
- A websocket with the path token reaches the app with `root_path` set.

**Rejected with 401**
- A token in the query string (`?token=`, `?access_token=`).
- Path near-misses:
  - the token in a later segment
  - a suffix on the token
  - the token missing its last character
  - the token in upper case
  - a nested prefix
  - `//mcp` and `/`
- Header near-misses:
  - lower-case `bearer`
  - a double space
  - a trailing space
  - a suffix on the token
  - the `Basic` scheme
  - the bare token
  - an empty `Bearer`
  - an empty header
- The token in `X-Api-Key` or in a cookie.
- Every 401 has the exact `WWW-Authenticate` value and the body `{"error": "unauthorized"}`, and the token appears in neither the body nor the headers.

**Other responses**
- Three `/.well-known/*` discovery paths return 404 `Not found` with no `WWW-Authenticate` header.
- A websocket without credentials is closed with code 1008, and the inner app never runs.
- An outer `root_path` that the proxy did not strip gets 401. This is documented behaviour: the proxy must strip its own prefix.

### Full FastMCP app (in process)

**Guard order**

The guards run in a fixed order:

1. The Host check runs first: a bad Host with a valid token gives 400.
2. The Origin check runs next: a bad Origin gives 403.
3. The token check runs last: no credentials gives 401.

With the right Host and the path token, `initialize` gives 200.

**Other checks**
- With a token and no explicit list, a random `trycloudflare.com` Host works.
- The no-token loopback app still answers `initialize` with 200.

### `main()` wiring
- In the source:
  - the order-tool and shell-tool switches are resolved before `_ensure_dotenv()`
  - the token is read after it
  - `sys.exit(2)` and `access_log=not token` are present
- `--help` lists `--token`, `--allowed-hosts`, `--enable-order-tools` and both env names.
- The module docstring mentions `--enable-order-tools`, ADR 0008, `VIBE_CRYPTO_MCP_TOKEN` and the `/<secret>/mcp` URL form.
- Integration:
  - `--token tooShort9` exits 2 with the validation message and does not echo the token.
  - An invalid token in `~/.vibe-trading/.env` is picked up and causes exit 2 with the validation message, which proves the `.env` token is read.

### Order tools
- **Parameter mapping:**
  - `None` values are dropped.
  - Defaults are `market` and `day`.
  - `notional` alone is passed through.
  - A limit order keeps `limit_price`, and `gtc` and `account` are passed through.
  - Cancel works with and without `symbol` and with `connection_id`.
- **Docstring:** the safety rules are present (sandbox, mandate, kill switch, explicit confirmation, never retry, exactly one of quantity or notional).
- **Registration:**
  - Registering twice and unregistering twice leaves the tool set as it was, and the tools can be registered again afterwards.
  - The annotations are `idempotentHint` False and `openWorldHint` True.
  - The input schema requires exactly `symbol` and `side`, and `side` is limited to buy and sell.
  - An invalid `side` is a tool error and never reaches the registry.
- **Env switch:**
  - `1`, `true` and `yes` turn it on.
  - `0`, an empty value and `no` leave it off.
  - The CLI opt-in wins over an env value of `0`.

## Findings

1. **`test_T01` still fails, as the developer reported.** The failing test is `agent/tests/vibe_crypto/test_T01.py::test_no_internal_identifier_was_renamed_to_a_crypto_variant`. It flags every `VIBE_CRYPTO_MCP_*` string in the implementation, in `.env.example` and in the developer tests. The owner of that test needs to allow-list `VIBE_CRYPTO_MCP_` and `VIBE_CRYPTO_WITH`. If that test scans `agent/tests/vibe_crypto`, it also flags `test_T15.py`, because these tests have to name the env keys.
2. **`remove_tool` is deprecated.** `_unregister_order_tools` uses `mcp.remove_tool`, which emits a `FastMCPDeprecationWarning` (132 in this file). The non-deprecated call is `mcp.local_provider.remove_tool`.
3. **Outer `root_path` gets 401.** When a reverse proxy forwards with its own outer `root_path` still in the path, the token guard sees the proxy prefix as the first segment and returns 401. Cloud Run and tunnels do not add a prefix, so this does not matter for the shipped guides. Note it if someone mounts the server under a sub-path.
4. **Docstring placeholder differs.** The module docstring uses `/<secret>/mcp`, while the handoff and the CLI help use `/<token>/mcp`. This is cosmetic, and the test accepts both.
